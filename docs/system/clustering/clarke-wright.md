# Clarke-Wright

**Идея.** Сначала каждый заказ — отдельная поездка. Затем пары поездок жадно объединяются, если вместе их обслуживать дешевле, чем по отдельности; решение принимается по тому, сколько расстояния экономит объединение.

## Как работает

1. На каждом складе сначала каждый заказ — отдельный маршрут.
2. Для каждой пары заказов одного склада считается значение экономии:

    $$
    s_{ij} = d(0, i) + d(0, j) - d(i, j) + \varepsilon
    $$

    где \(d(0, \cdot)\) — расстояние до склада, \(d(i, j)\) — расстояние между заказами, \(\varepsilon\) — шум, равномерно распределённый на отрезке \([-\eta, \eta]\). Уровень шума \(\eta\) выбирается для каждого варианта независимо, чтобы варианты были разнообразнее.

3. Пары обрабатываются по убыванию экономии. Пара объединяется, только если:
    - оба заказа сейчас стоят на концах своих маршрутов — так маршрут остаётся простой цепочкой и не ветвится;
    - общая масса не превышает вместимость самого вместительного типа транспорта.
4. Если известны тарифы, перед объединением выполняется проверка по стоимости: объединение принимается не всякий раз, когда позволяет вместимость, а только когда оно выгодно.

## Проверка по стоимости

Пусть \(t_a\) и \(t_b\) — наименьшие типы транспорта, вмещающие каждый маршрут по отдельности, а \(t_+\) — больший из них.

- Стоимость раздельного обслуживания \(c_{sep}\) считается для \(t_a\) и \(t_b\) соответственно, без учёта расстояния: расстояние учитывается только через значение экономии.
- Для объединённого маршрута рассматриваются два типа: \(t_+\) и следующий тип выше, \(t_{++}\), если он есть. Для каждого типа t:

    $$
    c_t = fixed_t + transport_t + per\_order_t \cdot (n_a + n_b) + per\_kg_t \cdot (M_a + M_b) - per\_km_t \cdot s
    $$

    где \(n_a, n_b\) — число заказов в маршрутах, \(M_a, M_b\) — их массы; значение экономии s вычитается как расстояние, которого удалось избежать.

- Объединение принимается, только если меньшая из двух стоимостей строго меньше \(c_{sep}\).
- Итоговый тип объединённого маршрута — всегда наименьший тип, вмещающий его итоговую массу, независимо от того, какой тип использовался в проверке.

На этом этапе маршрут хранит только список заказов и два конца, нужные, чтобы решать, какие объединения допустимы. Порядок доставки определяется позже, на этапе маршрутизации.

??? note "Псевдокод"
    ```
    procedure ClarkeWright(orders, depot, η, τ)
        savings ← ∅
        for each pair (oi, oj) in orders do
            ε ← uniform(−η, η)
            s ← d(depot, oi) + d(depot, oj) − d(oi, oj) + ε
            add (s, oi, oj) to savings
        end for
        sort savings by s descending
        R ← one singleton route per order              ▷ route → orders, two endpoints
        for each (s, oi, oj) in savings do
            ri, rj ← routes of oi, oj
            if ri = rj or oi, oj not both route endpoints then
                continue
            end if
            M ← mass(ri) + mass(rj)
            if M > capacity of the largest courier type then
                continue
            end if
            if τ given then
                ta, tb ← smallest type fitting mass(ri), mass(rj)
                c_sep ← cost(ta, ri) + cost(tb, rj)    ▷ no distance term
                t+ ← larger of ta, tb; t++ ← next tier above t+ (if any)
                best ← min over t ∈ {t+, t++} of cost_merged(t, M, s)
                if best ≥ c_sep then
                    continue
                end if
            end if
            merge ri and rj into one route; update its two endpoints
        end for
        return one cluster per remaining route, typed by its final mass
    end procedure
    ```
